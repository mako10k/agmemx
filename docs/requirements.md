# AIエージェント用メモリ

LLMに負担が少ない、メモリ管理プログラム。

負担が少ないとは、呼び出し側のメインコンテキストを汚さないことである。入出力は厳密なスキーマに乗せ、検証と拒否はメモリ側で完結させる。思考やリトライでメインコンテキストを増やす負担を、呼び出し側に載せない。

## 設計方針

1. 登録は自然文で行う。
2. 内部では、情報を関係構造として整理する。
3. 構造化する要素は、「信念」と「観測」を分離する。観測は事実とは別種別である。
4. 信念には理由を紐づけられるが、理由がなくてもよい。理由は信念、観測、自然文のいずれかである。
5. 観測には直接の理由が必要であり、信念を理由としては使わない。直接の理由は発話または文書のスパンであり、意味としてはそのコンテキストを同梱する。保持は Reference とし、本文の複製を前提にしない。
6. 時系列は関係として保持する。同じ文脈で次に発言したなどの順序と、期間の両方を持つ。
7. 検索も自然文で行えるようにする。
8. 信念・観測は、それぞれ構造化された形で応答できるようにする。応答のフィールド構成は仮決めとし、使いながら調整する。
9. 過去の信念・観測と、その理由を後から登録できるようにする。
10. 会話ドメイン（文脈）を後付けで整理できるようにする。
    - 同じ表現でも文脈によって意味が異なる場合を扱う。
11. 埋め込みを使った意味検索を、初期の検索経路に含める。
    - プロバイダは実行時に一つ選ぶ。初期の実装はローカルの Ollama と OpenAI であり、追加の接続先は OpenAI 互換の base URL で指定する。
    - モデル名は呼び出し側が指定する。プロバイダまたはモデルが異なるベクトルは比較しない。
    - ベクトルは再生成できるキャッシュに置く。鍵は環境変数に置き、記憶本体にも文書にも書かない。
12. 解釈構造に多様性を持たせる。
    - 遡って前提や仮説を登録できるようにする。
    - 矛盾はシステム状態として持たない。矛盾しているという信念を、対象へのリンクで表す。

## 確定した制約

### 観測と Reference

- 観測の直接の根拠は、発話または文書のスパンである。
- その意味には、スパン単体ではなく周囲のコンテキストが含まれる。
- データ構造は Reference で表す。源と範囲を指し、コンテキストは参照先から解決する。
- 観測は、世界について確定した事実ではない。事実という種別は置かない。

### 信念の理由

- 理由は無くてよい。
- ある場合は、信念、観測、自然文のいずれかである。
- 観測の理由スロットに信念は入らない。

### 矛盾

- 矛盾という専用の状態、辺、解消手続きは持たない。
- 矛盾は、矛盾しているという内容の信念が、対象の信念または観測へリンクすることで表す。

### 時間と文脈上の順序

- 同一文脈における順序を関係として持つ。例は、同じ文脈で次に発言した、である。
- 期間も持つ。
- 期間が指すもの（発言の時間幅、内容が当てはまる期間、登録時刻）の切り分けは、順序と期間を持ったうえで様子を見る。

### 呼び出し境界

- 登録、検索、更新、拒否は厳密なスキーマで行う。
- スキーマ違反はメモリ側が拒否し、呼び出し側に修復の思考をさせない。
- 検索結果は、メインコンテキストに生の履歴を展開する代わりに、構造化された信念と観測を返す。

## 仮決め

- 応答1件のフィールド構成は固定しない。識別子、種別、本文、期間、理由または Reference、文脈、順序関係を起点に、使いながら増減する。

## 配置とドメイン

配置、階層ドメイン、`--dir`、開発由来の sealgraph 規則は [architecture.md](architecture.md) に定める。

- 信念・観測・Reference は `${XDG_DATA_HOME:-$HOME/.local/share}/agmemx/` に置く。
- ドメインは実行時ディレクトリの正規化絶対パスをノードとする木である。`--dir` で解決ディレクトリを変更できる。
- 文書・ソース・テストの由来は作業ツリーの sealgraph に記録し、文書更新の影響範囲をそこから辿る。
- 埋め込み索引はキャッシュであり、プロバイダとモデルの組ごとに分ける。接続先の規則は [architecture.md](architecture.md) に定める。

## 参考になりそうな類似研究

- Reflective Memory Management for Long-term Conversational AI
  - 長期会話向けのメモリ管理で、将来の検索を意識した記録と、過去の検索結果を反映して改善する仕組みが提案されています。
- APEX-MEM: Agentic Semi-Structured Memory with Temporal Reasoning for Long-Term Conversational AI
  - 半構造化メモリと時系列推論を組み合わせた長期会話メモリです。
- SmartSearch: How Ranking Beats Structure for Conversational Memory Retrieval
  - 会話メモリ検索では、複雑な構造化よりもランキング型検索が有効な場合があることを示しています。
