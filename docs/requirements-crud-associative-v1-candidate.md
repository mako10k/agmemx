# agmemx CRUD・CLI・連想検索 要件候補 v1

状態: Candidate（2026-09-28）。`v1` はこの要件候補の文書版であり、製品版・公開 API 版・CLI 契約版ではない。所有者による承認前であり、現行の [requirements.md](requirements.md)・設計・実装・PERT を置き換えない。

## 目的と由来

AI エージェントおよび人が、保存した記憶を登録後にも見つけ、内容を確かめ、修正し、不要なものを除き、関連する前後の文脈とともに取り出せるようにする。現行の信念・観測、理由、Reference、`next`、ドメイン、埋め込み検索の意味は、以下で明示する変更を除き [requirements.md](requirements.md) の制約を引き継ぐ。

今回の所有者指示は、Read に一覧・検索を含めた CRUD の完備、対称で一貫した CLI、既存 CLI との互換を完了条件にしないこと、Git や Docker と同じコマンド名なら意味を十分に揃えること、検索精度だけでなく近接リンクから人が連想できる手掛かりを返すこと、A→B→C の B の前後を辿れること、プリミティブな入力を原則 `--option=value` 等で渡し JSON 入力を任意経路にすることである。以下の具体化は承認待ちの提案である。

## 提案する対象と操作

| 対象 | Create | Read | Update | Delete |
| --- | --- | --- | --- | --- |
| 信念 | 登録 | ID 指定取得・ドメイン部分木の一覧・自然文検索 | 本文、理由、対象、期間、所属ドメインを変更 | ID 指定削除 |
| 観測 | Reference 付き登録 | ID 指定取得・ドメイン部分木の一覧・自然文検索 | 本文、Reference、期間、所属ドメインを変更 | ID 指定削除 |
| `next` 関係 | 同一ドメインの両端を結ぶ | 関係の識別子による取得・ドメイン内の一覧・端点からの参照 | 両端を変更 | 関係の識別子による削除 |

「完備」は、上記の各操作が公開 CLI で実行でき、成功結果を機械向け JSON で読み戻せることを指す。ID 指定取得と一覧は埋め込みプロバイダを要求しない。自然文検索だけが埋め込みを使う。全操作は、指定したドメインの可視範囲と既存の種別・理由・Reference・同一ドメイン `next` 制約を守る。

更新後も記録 ID は維持し、内容ダイジェストと埋め込みキャッシュは変更内容に合わせる、という案とする。参照元が残る信念・観測の削除、または端点が使われる更新は、暗黙の連鎖削除や参照切断をせず拒否する案とする。失敗時には対象記録・関係・所属索引・キャッシュの部分更新を残さない。削除済み ID の取得・再削除は、存在しない対象として拒否する。

ドメインはファイルシステム上の文脈・可視範囲であり、この候補では記憶レコードの CRUD 対象には含めない。既存のドメイン初期化、所属の付け替え、部分木解決は利用できるものとする。埋め込み設定・再索引は運用操作であり、記憶レコードの CRUD とは区別する。

## CLI 入出力

公開コマンドは対象ごとに同じ操作語と引数順を用い、対応する操作の有無が `help`・`schema`・補完・man と一致する。対象と操作が違うだけで入力名・成功形・拒否の意味が変わる場合は、その違いを対象固有の制約として説明する。Git・Docker と同じ名前を使う場合は利用者が期待する主な意味と揃え、揃わない名前は採用しない。具体的なコマンド綴りと JSON フィールドは設計・CLI 契約で定める。

本文、ID、期間の両端、Reference の源と範囲、理由の種別と ID、関係の種別と両端、ドメイン、検索語・件数など、プリミティブ値で表せる入力はコマンド引数・`--option=value` 形式で指定できる。複数値や入れ子の指定が必要な場合も、意味を曖昧にせず表せる範囲では反復オプションや分割オプションを提供する。JSON オブジェクト入力も選べるが、プリミティブ値だけの通常操作の必須条件にはしない。同一呼び出しで引数入力と JSON 入力を混在させる場合の優先・拒否規則は一つに定め、曖昧な部分実行をしない。

人向け text と機械向け JSON の双方で、取得・一覧・検索の対象識別子と内容を確認できる。text 表示は構造上の関係を見失わないようにし、JSON は厳密なスキーマと安定した拒否を維持する。互換エイリアスの維持や既存の綴り・応答形との後方互換は、この候補の完了条件にしない。ただし保存済み記憶を自動で破壊する変更は、別に許可された移行・削除手順なしには行わない。

## 連想検索

自然文検索は、まず現行のドメイン部分木と埋め込みによる一致候補を選ぶ。類似度は入口の選択に使い、出力の価値を一致順位だけで測らない。各一致候補には、`next` の直接前後に加え、信念の理由と `about` の直接リンクでつながる可視範囲内の記録を、検索語との類似度に関係なく想起の手掛かりとして添える。例えば A→B→C が保存され、B が一致候補なら、B を中心に A と C が前後どちらか分かる。理由・`about` の手掛かりにはリンク種別と方向を付け、時系列の前後と混同させない。

一致候補と手掛かりの各記録には、識別子・種別・ドメイン・短い表示用の手掛かりを含める。保存されたタイトルが利用できる場合はそれを使い、無い場合も保存本文の短い抜粋など、元の記録に遡れる表現を示す。保存されていない要約や関係の意味を事実として作らない。候補本体と手掛かりは区別し、手掛かりを一致順位・一致件数に混ぜない。結果に含まれる ID を使って本文の取得や関係一覧へ進める。

検索の件数上限は一致候補に適用し、手掛かりは別枠で上限を設ける。少なくとも A→B→C の一つの前後リンクは両方表示できるようにする。無制限に関係グラフを展開せず、同一記録が複数経路に現れた場合も識別子で照合できる。Reference は源と範囲を維持し、源ファイル全体を検索結果へ複製しない。Reference 周辺本文の自動同梱範囲は本候補では決めず、必要なら別途受入条件を定める。

## 受入の最低例

1. 一時 XDG 領域で信念・観測・`next` を引数だけで作成し、各対象を ID 指定取得と一覧で読み戻せる。等価な JSON 入力経路も確認できる。
2. 各対象の更新を取得で確認し、変更対象以外の ID・関係・索引が意図せず変わらない。既存制約に反する更新と失敗する埋め込みは、部分更新を残さない。
3. 参照中レコードの削除は拒否され、関係を明示的に削除した後でレコードを削除できる。削除後の取得・一覧・検索には現れない。
4. A→B→C を登録し、B にだけ類似する語で検索したとき、B を一致候補として、A と C の短い手掛かりを前後の文脈として区別して返す。さらに B の理由・`about` で直接つながる別記録の手掛かりを、関係種別とともに返す。手掛かりの低い類似度は除外理由にならず、件数上限は一致候補にのみ効く。
5. 全公開操作の help・schema・text・JSON・補完・man が同じコマンド体系を示し、プリミティブ操作には JSON 入力を要求しない。

## 所有者に残す決定

1. CRUD の対象を上表の記憶レコード三種とし、ドメイン自体や埋め込み設定は除くか。ドメインまで CRUD にするとディレクトリ実体や既存記憶への作用を別途定義する必要がある。
2. 更新で ID を維持し、参照中の削除を拒否するか。新 ID で置換する案は履歴を明示できる一方、既存参照の扱いを別途決める必要がある。連鎖削除案は操作数を減らせる一方、意図しない消去範囲が広がる。
3. `next`・理由・`about` の直接リンクを想起の手掛かりとする案でよいか。Reference 周辺本文の自動同梱と、さらに遠いリンクまでの自動展開を追加する案は一回の検索で多く読める一方、出力量と境界条件が増える。手掛かりの件数上限と、上限超過時の選択規則も定める必要がある。
4. 既存保存形式からの移行・旧 CLI 利用者の範囲に保護対象があるか。後方互換を不要とする指示は確認済みだが、既存データの消去や自動移行の許可とは区別する。
