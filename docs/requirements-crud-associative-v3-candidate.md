# agmemx CRUD・CLI・連想検索 要件候補 v3

状態: Candidate（2026-09-28）。v3 は要件文書の候補版であり製品版ではない。v1 の独立レビュー後の `REVISE` と v2 への所有者訂正を反映した。承認前であり、現行の [requirements.md](requirements.md)、設計、実装、PERT を置き換えない。

## 目的と由来

AI エージェントと人が、記憶を登録後にも見つけ、確かめ、訂正し、後から変わった見解や判明事項と結び、不要な記録を除き、関連文脈とともに取り出せるようにする。現行の信念・観測、理由、Reference、`next`、ドメイン、埋め込み検索の制約は、ここで明示する変更を除き [requirements.md](requirements.md) を引き継ぐ。

所有者が指定した変更は、Read に取得・一覧・検索を含む CRUD、対称で一貫した CLI、プリミティブ入力には引数やオプションを使えること、Git・Docker と同名のコマンドを使うなら主要な意味を揃えること、近接リンクを示す連想検索である。CLI と保存データの後方互換は一切要求せず、破壊的な切替を許す。ドメインは canonical path に対応し、ディレクトリ移動に対応する。以下の具体化は承認待ちの提案である。

## CRUD の対象と操作

| 対象 | Create | Read | Update | Delete |
| --- | --- | --- | --- | --- |
| 信念 | 本文と任意の表示名を登録 | ID 指定取得、ドメイン部分木の一覧、自然文検索 | プリミティブな訂正、理由・対象・期間・所属の訂正 | ID 指定削除 |
| 観測 | 本文と Reference、任意の表示名を登録 | ID 指定取得、ドメイン部分木の一覧、自然文検索 | プリミティブな訂正、Reference・期間・所属の訂正 | ID 指定削除 |
| 記録間の関係 | `next` や記憶の変化を表す有向リンクを登録 | 関係の取得・一覧、端点からの参照 | 関係内容の訂正 | 関係の削除 |

ドメインそのものと埋め込み設定は CRUD 対象から除く。ドメインはディレクトリの canonical path に対応する文脈・可視範囲であり、記録の所属付け替えと部分木の解決はできる。ディレクトリ移動で canonical path が変わっても記録を新しい path に対応付ける手段を提供し、移動したディレクトリの子孫 path を含む対象記録の ID・本文・理由・`about`・`next`・変化リンクの整合を保つ。移動の検出・通知方法は設計で定める。

取得・一覧・削除・関係操作・所属変更は埋め込みプロバイダを要求しない。本文の作成・訂正、自然文検索、明示的な再索引は埋め込みを使う。失敗した作成・訂正・関係変更・削除は記録、参照、関係、所属索引、埋め込みキャッシュに部分更新を残さない。

### 訂正と記憶の変化

メモリの更新には二つの異なる意味がある。

1. **プリミティブな訂正**: 登録時の typo や更新ミスを直す。記録 ID を変えず、同じ記録の内容を変更する。関係や参照を壊さず、本文が変われば検索用キャッシュを更新する。これは過去の見解の変化を表す操作ではない。
2. **時系列・新事実による変化**: 当時の記録を残し、新しい内容を別記録として登録し、古い記録から新しい記録への有向の変化リンクを作る。変化の理由・根拠をリンクに結び付けられる。リンクを辿ると、何から何へ見解または把握内容が変わったか、登録された理由・根拠は何かが分かる。検索結果でも旧・新の記録と変化の方向、登録された理由・根拠を区別して示す。元の記録を同じ ID で上書きしない。

CLI はこの二つの意図を異なる操作として区別する。本文の差分だけで訂正と見解の変化を推定しない。変化リンクと時系列 `next` は別の意味を持つ。参照中の記録を削除するときは暗黙の連鎖削除やリンク切断を行わず拒否し、参照・リンクを明示的に整理した後で削除できる。

## CLI 入出力

公開コマンドは対象ごとに同じ操作語と引数順を用い、対応する操作の有無を `help`、`schema`、補完、man に一致させる。同名操作の主要な意味を対象によって変えない。Git・Docker と同じ名前を使う場合は利用者が期待する主な意味と揃え、揃わない名前は採用しない。具体的なコマンド綴り、関係の識別方法、JSON フィールドは設計・CLI 契約で定める。

本文、表示名、ID、期間の両端、Reference の源と範囲、理由の種別と ID、関係の種別・両端・理由、ドメイン、検索語、出力予算など、プリミティブ値で表せる入力はコマンド引数または `--option=value` 形式で指定できる。複数値も意味を曖昧にせず表せる範囲では反復オプションや分割オプションを提供する。JSON オブジェクト入力も任意で選べるが、プリミティブ値だけの通常操作に必須としない。両入力経路を混在させる場合は一つの明確な優先・拒否規則を持つ。

人向け text と機械向け JSON で、取得・一覧・検索の記録 ID、内容、関係を確認できる。成功形と拒否は厳密なスキーマを持つ。互換エイリアス、旧コマンド・旧応答形、旧保存形式の読取・変換・保全は要求しない。旧データに関する追加の移行手順を要件化しない。

## 出力予算内の連想検索

自然文検索は、ドメイン部分木と埋め込みで一致候補を選ぶ。一致候補には直接の `next` 前後、理由、`about`、変化リンクから辿れる記録を連想の手掛かりとして加える。手掛かりは自身の類似度が低くても除外しない。A→B→C の B が一致したときは A が前、C が後と分かり、B の変化前後の記録や理由も `next` とは異なる関係として分かる。候補本体と手掛かりを区別し、手掛かりを一致件数・順位に混ぜない。

各候補には、参照されている数、関係の種別・方向ごとの接続数、Reference の利用状況などの統計を付ける。表示する短い要約は保存本文、表示名、Reference の解決可能な文脈に基づき、由来のない意味を事実として追加しない。Reference の源と範囲は保持し、参照先を解決できない場合は記録を消さず、その状態を示す。

検索表示は指定された出力予算を守る。重み付けで、候補の関連度に加え、参照・接続の統計、リンクの種類と方向、時系列の前後、見解の変化を考慮し、予算内に入る候補・手掛かり・要約の量を選ぶ。限られた予算でも候補 ID と関係方向を優先し、省略があれば件数または省略の事実を示す。予算の単位と既定値、統計の厳密な定義、重み・選択・切詰め規則は設計・CLI 契約で決め、同じ保存状態と入力なら結果を再現できるようにする。ID から元の記録と関係全体へ進める。

## 受入の最低例

1. 一時 XDG 領域で信念・観測・関係を通常の引数だけで作成し、各対象を取得・一覧で読み戻せる。等価な JSON 入力経路も確認できる。ドメインと埋め込み設定の CRUD は公開しない。
2. typo 訂正後に同じ ID から訂正済み本文が得られ、無関係の記録・参照・関係は変わらない。埋め込み失敗や不正な参照では、記録・索引・キャッシュに部分更新を残さない。
3. 古い見解と新しい見解を別 ID の記録として保持し、理由・根拠を含む有向の変化リンクから両方を辿れる。検索で片方が一致すると、出力予算の範囲で相手の ID、変化方向、理由・根拠の存在が分かる。元記録の本文は変わらない。
4. A→B→C を登録し、B にだけ類似する語で検索すると、B を一致候補として、A と C の前後関係を手掛かりに表示する。理由・`about`・変化リンクを時系列関係と区別し、予算を縮めた場合も省略を明示する。参照数などの統計と重みを使った選択は、同じ入力で再現できる。
5. 参照中の記録の削除は拒否され、参照やリンクを明示的に整理すれば削除できる。削除後は取得・一覧・検索に現れない。全公開操作の help・schema・text・JSON・補完・man が同じ体系を示す。
6. ディレクトリの canonical path が移動した後、提供された対応付け手段により、新 path から対象記録の同じ ID・本文・関係を取得・一覧・検索できる。無関係のドメインは変わらない。

## 次の設計で決めること

関係の識別子と訂正方法、ディレクトリ移動の検出または通知手段、検索統計の計算法、出力予算の単位・既定値・重み・要約方式、CLI の正確な綴りと JSON スキーマを設計で具体化する。これらの選択は、訂正と記憶の変化の区別、関係方向、予算内表示、後方互換不要という要件を変更できない。
